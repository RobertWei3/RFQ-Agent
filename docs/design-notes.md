# 设计说明

> 本文由作者本人填写。每节下的引用块是“这里写什么”的提示，填写时删掉即可。
> 自建版本的实现细节见 [RFQ-SPEC.md](../RFQ-SPEC.md) 与 [docs/plans/](plans/)，术语见 [GLOSSARY.md](../GLOSSARY.md)。

## 1. 原系统概述（平台版本）

> 原系统要解决什么业务问题、谁在用、规模多大；在平台上由哪些步骤或 agent 组成，各自用了哪些工具和数据源；上线后的效果。

## 2. 为什么拆成四个 agent

> 为什么按 OE 解析、MSRP、零售价、应有成本这样拆，而不是一个大 agent 或更细的拆法；拆分带来了什么（单独测试、并行、换模型），付出了什么。

## 3. 阶段契约的设计

> 阶段之间传什么、为什么用固定的 schema；结构化输出校验失败怎么处理；“防编造”这类核对放在 LLM 还是代码里，界线怎么划。

## 4. 实体消解的难点

> 客户件号、OE 号、零售标题件号为什么容易混；替代链、一对多、多对一分别难在哪里；哪些判断交给确定性代码、哪些交给 LLM。

## 5. 分批与容错

> 为什么按批运行；单行失败、整批失败、进程中途被杀分别怎么处理；断点续跑和重跑失败行的设计取舍。

## 6. 置信度策略的选择与评估结果

> 三种策略各自的想法；用什么数据和指标比较（可引用 README 的评估结果摘要）；最后选了哪一种、为什么，还有哪些没解决的问题。

## 7. 平台方案 vs 自建方案的取舍

> 结合两个版本的实际体验，按下面几个维度逐一比较，最好每条都有具体例子。
>
> - 开发速度
> - 可控性
> - 可观测性
> - 成本
> - 可测试性
> - 厂商锁定

## 8. 如果上生产还需要什么

> 从这个复现版本到生产系统还差什么：真实数据源、权限与多租户、监控告警、评估数据集、人工复核流程、部署与成本控制等，按优先级排列。
